## 当前课堂演示方案

线上服务使用 CloudBase 文档数据库保存账号、登录会话、用户进度和目标草稿，并把云托管限制为最多一个实例。单个实例仍可同时处理多个用户；后端会把涉及共享运行状态的请求排队执行，避免同一用户的并发写入互相覆盖。数据保存在文档数据库中，因此容器休眠、重启或重新部署后不会丢失账号和进度。

该方案使用现有 CloudBase 个人版套餐的免费额度，`EnableOverrun=false`，超过套餐额度时服务会停止，而不会自动产生超额费用。它适合课程演示和小规模同时使用，不作为高流量生产容量承诺。

## 已验证范围

- `npm test`：后端语法、业务回归、小程序结构检查、文件模式双用户隔离、重复结算保护、重启恢复和 API 冒烟测试。
- `npm run test:mysql-concurrency`：20 个独立账号、2 个 Node 进程、40 次并发写入，验证用户隔离、重复完成只结算一次和进程重启恢复。该测试只验证兼容的 MySQL 实现，线上免费方案不使用 TDSQL-C。
- `npm run test:cloudbase-multi-user`：在真实 CloudBase 文档数据库中创建两个随机账号，并发写入两个不同任务，验证彼此不可见；关闭并重新启动后端后，用新客户端重新登录并恢复各自数据；测试结束后清理临时账号、会话和状态文档。
- 小程序 API 冒烟：覆盖目标草稿、来源选择、计划确认、注册、任务、角色记忆、副本和再次登录。
- 微信开发者工具：通过真实 `wx.cloud.callContainer` 检查线上 `/healthz` 和 `/api/roles`。

## 数据隔离实现

- 账号文档 ID 使用规范化账号的 SHA-256，账号密码使用 `scrypt` 派生后保存，不保存明文。
- 登录会话按 token 哈希存储，每次请求先解析会话，再加载对应 `userId` 的状态文档。
- 用户状态以 `userId` 为文档 ID，账号 A 的请求不会加载或覆盖账号 B 的状态。
- 匿名目标草稿同时绑定客户端 ID，其他客户端无法读取。
- 云托管最多一个实例，确保现有进程内排队机制对所有课堂请求有效。

## 限制

- 单实例吞吐量有限；高流量生产环境应增加按用户的分布式锁或乐观并发控制后再扩容到多实例。
- 尚未覆盖长时间压力、云服务故障切换、不同真实手机上的持续高并发以及外部 AI/搜索接口的负载。
- DeepSeek 或搜索服务不可用时，相关智能功能可能降级；账号、登录和本地业务数据仍由 CloudBase 保存。
