# 《自律者联盟》比赛版 MVP 项目文档

## 1. 项目定位

### 1.1 项目名称
《自律者联盟》

### 1.2 项目一句话介绍
一个将学习目标拆解为可执行任务，并由 AI Agent 持续记录学习过程、转化为角色冒险故事，再通过夜间副本反馈成长的 AI 学习产品。

### 1.3 比赛版目标
本项目面向小型比赛场景，重点不是做完整商业产品，而是做出一个可以稳定演示、逻辑清晰、亮点明确的 MVP。

比赛版重点验证 3 件事：
- AI 能把用户输入的短期学习目标拆成清晰的 TODO 任务
- AI Agent 能把学习记录转化为个性化角色冒险故事，不同用户可以生成不同的 Agent 与剧情体验
- 每天晚上 10 点开放的小游戏副本，能把白天的学习进度转化为可感知的角色成长反馈

### 1.4 对标 Habitica 后的简化思路
借鉴 Habitica 的任务驱动成长思路，但只保留最适合比赛展示的部分：
- 保留注册初始化、角色选择、目标拆解、TODO-list、角色成长、剧情反馈、角色日记、夜间副本
- 保留“完成任务就推进主线剧情”和“自主加任务可触发支线剧情”的核心机制
- 角色选择不代表学习习惯，而是用于决定故事风格、世界观包装与主线表达
- 不做复杂社交、公会、排行榜、真实多人互动
- 不做复杂商城经济系统、重度数值养成和长线运营玩法

## 2. 目标用户与使用场景

### 2.1 目标用户
- 有明确短期学习目标的学生
- 正在备考的大学生，例如 CET-6、考研、期末考试
- 对传统待办工具缺乏动力，希望把学习过程变得更有代入感和成就感的用户

### 2.2 核心场景
用户进入产品后，先选择一个角色风格并输入短期学习目标，例如“30 天备考 CET-6”。系统基于目标生成专属 AI Agent、初始世界观与主线剧情，并拆解出当前阶段的 TODO 任务。用户在白天逐步完成任务，AI Agent 记录学习内容并生成角色冒险故事；若用户临时增加任务，系统会将其包装为支线剧情。当天晚上 10 点，副本入口开放，用户可以进入一个简单的肉鸽小游戏中体验角色成长。需要注意的是，“夜间副本”和“主线续写”是两条并行机制：当当前阶段主线任务全部完成时，系统应立即弹出输入框，要求用户输入下一阶段目标，并生成新一轮主线与剧情，而不是等到副本结束后再继续。

## 3. 产品核心价值

### 3.1 用户痛点
- 学习目标太大，不知道如何开始
- 每天缺少清晰计划，容易拖延
- 学习完成后只有“做完了”，缺少连续记录和情绪反馈
- 普通待办工具太单调，难以形成长期记忆点和投入感

### 3.2 解决方案
- 用 AI 将抽象目标拆解为当前阶段可执行的任务列表
- 用 AI Agent 记录学习过程，把任务完成转化为角色成长与冒险故事
- 用角色选择来定义故事风格与主线，而不是给用户贴学习习惯标签
- 用角色面板、技能装备、角色日记和夜间副本建立完整的成长反馈闭环

## 4. 比赛版 MVP 功能范围

## 4.1 必做功能

### 4.1.1 注册界面与角色设定
用户首次进入时，在注册界面完成初始化信息填写。

输入项建议：
- 昵称
- 短期学习目标
- 目标截止时间
- 每天可投入时长
- 角色选择
- 简单初始属性或偏好标签

角色设计原则：
- 角色不代表学习习惯，不用于判断用户属于哪种学习类型
- 角色的作用是决定 AI 生成故事的风格、世界观包装和主线基调
- 不同用户可以基于不同角色生成不同的 Agent 形象、开场剧情和叙事语言

首发角色建议：
- 守望骑士：偏史诗感、使命驱动、主线推进明确
- 奥术学者：偏探索感、知识收集、世界观信息丰富
- 荒野旅人：偏冒险感、事件邂逅、支线体验更强

比赛版简化规则：
- 不做复杂捏脸系统
- 只提供少量角色模板、默认立绘或头像
- 角色差异主要体现在文案、配色、剧情主线与剧情表达风格

### 4.1.2 输入短期目标与 AI 初始化
用户完成注册后，输入短期目标，系统进行 AI 初始化。

AI 初始化输出内容：
- 目标拆解后的 TODO-list
- 初始世界观设定
- 当前主线任务说明
- 专属 Agent 名称或称号
- 开场剧情文案

示例：
- 用户输入：“30 天备考 CET-6”
- 系统输出：“你将以见习学者身份进入失落语境之塔，当前主线为收集 3 枚词汇符印并修复阅读回廊”

比赛版实现建议：
- AI 负责“目标拆解 + 剧情定制 + 世界观初始构建”
- 提前固化 1 至 2 套高质量目标案例，保证演示稳定
- 当 AI 不可用时，可降级为固定模板 + 参数替换

### 4.1.3 AI Agent 学习记录与冒险故事生成
系统需要设计一个 AI Agent，在用户完成学习任务后记录学习内容，并将学习记录转化成一段角色冒险故事。

核心要求：
- 每完成一个任务，生成一条简短的成长反馈
- 每完成一组关键任务，生成一段新的剧情推进
- 不同用户、不同角色、不同目标下，生成的 Agent 设定和故事内容应有差异

输出形式建议：
- 今日成长记录
- 当前章节标题
- 一段 80 至 150 字的剧情文本
- 本次获得的成长值、技能点或装备奖励

比赛版实现建议：
- 主线结构固定，AI 负责把用户的学习记录映射进剧情
- 每次生成内容长度控制较短，保证页面展示稳定
- 若比赛时间紧，可将故事生成拆成“固定模板 + AI 润色”

### 4.1.4 TODO-list 与主支线任务
TODO-list 是用户的核心操作页面，用于承载 AI 拆解出来的任务，也支持用户自主修改和新增任务。

页面需支持：
- 查看任务名称、预计时长、任务类型、状态
- 标记任务完成
- 编辑已有任务
- 自主新增任务
- 当最后一个主线任务完成时，立即弹出新目标输入框

任务分类建议：
- 主线任务：由 AI 根据短期目标拆解生成，直接推动主线剧情
- 支线任务：由用户自主增加，AI 为其生成支线剧情包装

支线任务示例：
- 长期任务为“备考 CET-6”
- 用户临时增加“学习数据分析”
- 系统将该任务识别为支线，并为其生成独立支线剧情说明

任务状态建议：
- 未开始
- 进行中
- 已完成

### 4.1.5 角色面板与成长系统
角色面板用于集中展示用户当前的成长结果。

展示元素建议：
- 当前角色名称 / Agent 形象
- 当前等级或成长阶段
- 成长值 / 经验值
- 已获得技能
- 已获得装备
- 当前主线章节

建议规则：
- 完成 1 个主线任务：获得成长值
- 完成 1 个支线任务：获得较少成长值或特殊道具
- 当当前阶段最后一个主线任务完成：立即触发“输入下一阶段目标”弹窗，并在用户提交后生成新的主线任务和章节
- 成长结果会影响夜间副本的初始状态

### 4.1.6 装备、技能购买商店
用户可在成长过程中获得一定资源，用于解锁简单的技能或装备。

比赛版建议：
- 商店商品数量控制在 3 至 6 个以内
- 每个道具只需有基础名称、图标、效果说明
- 购买结果同步到角色面板，并在副本中体现简单效果

商品示例：
- 词汇符印：提高副本中的探索收益
- 专注披风：提高初始生命值
- 洞察卷轴：提高一次事件判定成功率

### 4.1.7 角色日记
角色日记用于沉淀用户已经完成的任务和已经历的剧情。

页面需支持：
- 按日期查看成长记录
- 查看已完成任务
- 查看已解锁章节与剧情文本
- 查看本次奖励和成长变化

角色日记的价值：
- 让学习过程具备“被记录”和“被讲述”的连续感
- 便于答辩时展示产品如何把学习过程转换成故事资产

### 4.1.8 游戏副本
每天晚上 10 点开放游戏副本，用户可以在一个简单的肉鸽小游戏中体验角色成长。

核心规则：
- 副本每天 22:00 开放
- 开放前显示倒计时或“尚未开启”
- 白天完成的任务、获得的技能和装备，会影响副本初始数值或可用能力
- 副本结束后生成结果反馈和新的剧情推进

比赛版简化建议：
- 做成轻量级肉鸽，不追求复杂战斗
- 可以采用 3 至 5 个事件房间、简单选择分支或轻量战斗
- 核心目标是让用户“感受到角色成长”，不是做完整独立游戏
- 提供演示快捷模式，方便答辩时模拟晚上 10 点开放场景

## 4.2 可选增强功能

如果时间充足，可以增加以下轻量功能：
- 连续完成天数展示
- 每日一句 AI 鼓励文案
- 角色立绘或头像轻量换装
- 剧情片段分享图
- 副本 Boss 或限时事件

## 4.3 为避免项目失控，本版不做以下内容

- 多人联机、公会、社交系统
- 复杂商城经济与稀有度体系
- 重度数值养成和平衡设计
- 复杂开放世界剧情树
- 高强度动作战斗或大型地图探索
- 完整商业化账号体系与强防作弊机制

## 5. 用户流程设计

## 5.1 主流程
1. 用户进入注册界面
2. 填写短期目标、选择角色、完成基础初始化
3. AI 完成目标拆解、剧情定制与世界观初始构建
4. 系统生成 TODO-list、主线剧情和专属 Agent
5. 用户白天逐步完成任务，也可自主添加支线任务
6. AI Agent 根据任务完成情况生成新的成长记录和剧情文本
7. 当当前阶段最后一个主线任务完成时，系统立即弹出输入框，要求用户输入下一阶段目标
8. 用户提交新目标后，系统重新生成主线任务、章节说明和剧情开场
9. 用户在角色面板、商店、角色日记中查看成长结果
10. 当天晚上 10 点进入副本，体验角色成长

## 5.2 按流程图梳理的模块关系
- 注册界面：填写目标、选择角色职业、配置简单属性
- 输入短期目标：AI 进行拆解、剧情定制、世界观初始构建
- TODO-list：拆解后的任务放在这里，用户也可以自主修改
- 装备、技能购买商店：用于消耗成长奖励并增强角色反馈
- 角色面板：查看属性、技能、装备、当前章节
- 游戏副本：每晚 10 点开启，体验角色成长
- 角色日记：查看已经完成的任务和已经历的剧情
- 任务推进结果：逐步完成任务，生成新剧情，获得角色成长
- 支线任务机制：用户自主添加的任务可作为支线任务，由 AI 设计支线剧情
- 主线续写机制：最后一个主线任务完成后，系统立即弹出输入框，要求输入下一阶段目标
- 完结循环：用户提交新目标后，系统立即进入下一轮主线剧情

## 5.3 比赛演示流程
建议答辩时按照固定剧本演示：

1. 首页展示项目主题与故事化学习设定
2. 用户进入注册界面，选择“奥术学者”角色
3. 强调角色只决定故事风格，不代表学习习惯
4. 输入“30 天备考 CET-6”作为短期目标
5. 展示 AI 生成的 TODO-list、世界观设定和主线开场剧情
6. 连续完成主线任务，展示 AI Agent 生成的成长记录与剧情推进
7. 完成最后一个主线任务后，展示系统自动弹出的“输入下一阶段目标”提示框
8. 临时新增一个任务，展示其被包装为支线任务
9. 进入角色面板与角色日记，查看成长变化
10. 演示晚上 10 点开放的副本入口与快捷模式
11. 总结项目亮点：AI 拆解 + AI Agent 叙事 + 主线续写弹框 + 夜间副本成长反馈

## 9. 技术实现建议

## 9.1 推荐技术栈
如果以快速开发和比赛演示为优先，建议采用轻量技术方案。

前端建议：
- Web：Vue 或 React
- UI：自定义 CSS + 少量组件库
- 副本实现：Canvas、DOM 卡片式事件流，或轻量 2D 方案均可

后端建议：
- Node.js + Express / NestJS
- 本地 JSON、SQLite 或轻量数据库均可

前后端分离建议：
- 前端只负责页面渲染、交互逻辑、状态展示与接口调用
- 后端统一负责目标拆解、剧情生成、任务状态、商店结算、副本时间判断
- 所有 AI 能力和规则判断尽量放在后端，避免前端写死业务逻辑

AI 接入建议：
- 任意可用的大模型 API
- 通过后端统一封装生成接口
- 预先缓存一组演示目标的生成结果

时间控制建议：
- 副本是否开放以服务端时间为准
- 比赛演示可增加 mock 时间开关或快捷模式

## 9.2 实现原则
- 先保证“注册 -> 生成任务 -> 完成任务 -> 生成剧情 -> 晚间副本”主链路跑通，再优化细节
- 先用规则和固定模板兜底，再接 AI 做个性化生成
- 角色差异先做文案和视觉差异，再考虑更复杂数值差异
- 副本先做轻量可演示版本，再考虑玩法扩展
- 始终准备 mock 数据，保证答辩时可稳定展示

## 10. 开发流程

以下按 2 周比赛冲刺节奏设计，可根据你们实际时间缩短或拉长。

## 10.1 第一阶段：需求确认与方案收敛（第 1-2 天）
目标：统一产品结构，锁定比赛版范围。

工作内容：
- 明确角色不代表学习习惯，而是剧情风格选择
- 确认注册界面、TODO-list、角色面板、商店、角色日记、副本的页面关系
- 明确主线任务、支线任务、剧情生成和副本开放规则
- 先产出 API 文档初稿和低保真原型

产出物：
- 功能列表
- 页面草图或低保真原型
- API 文档初稿
- 演示脚本初稿

## 10.2 第二阶段：基础链路开发（第 3-6 天）
目标：跑通从注册到任务生成的主流程。

工作内容：
- 按前后端分离方式搭建前端项目和后端 API 服务
- 搭建后端服务与基础数据结构
- 完成注册初始化、角色选择、目标输入、TODO-list 页面
- 完成 AI 初始化接口或 mock 数据联调

阶段验收：
- 能完成注册和角色选择
- 能输入目标并生成 TODO-list
- 能看到世界观开场文案和主线说明

## 10.3 第三阶段：成长闭环开发（第 7-10 天）
目标：跑通任务完成、剧情生成、角色成长和副本入口。

工作内容：
- 开发任务完成后的成长结算逻辑
- 开发“最后一个主线任务完成后自动弹出新目标输入框”的接口和前端交互
- 开发角色面板、角色日记、商店页面
- 开发 AI Agent 学习记录转剧情接口
- 开发副本开放状态、进入和结算逻辑

阶段验收：
- 完成任务后能生成成长反馈和剧情文本
- 角色面板与角色日记可正常展示
- 晚上 10 点副本逻辑可演示

## 10.4 第四阶段：联调、包装与演示优化（第 11-14 天）
目标：提升整体完成度，保证答辩稳定。

工作内容：
- 前后端全面联调
- 优化页面视觉和交互细节
- 增加演示快捷模式
- 完善文案、PPT、项目介绍和录屏备份

阶段验收：
- 整条演示链路无阻塞
- AI 接口异常时可切换到 mock 数据
- 副本、剧情、任务和页面切换稳定可演示

## 11. 前后端初始任务书

## 11.1 前端任务书

### 目标
负责把产品方案落地为可演示页面与交互，先完成信息架构、视觉风格、交互逻辑，再推进页面开发与接口联调。

### 初始任务清单
1. 完成页面信息架构梳理，明确首页、注册页、目标初始化页、TODO 主界面、角色面板/商店、角色日记、副本页之间的跳转关系。
2. 输出低保真原型，覆盖完整主流程，尤其要体现“注册 -> 任务生成 -> 完成任务 -> 主线完成弹框 -> 新目标生成 -> 晚间副本”的链路。
3. 完成页面风格设计，统一主视觉、配色、字体、按钮、卡片、弹窗、状态标签样式，并为不同角色预留风格差异。
4. 完成交互设计，明确任务完成后的反馈方式、剧情弹窗出现时机、主线完成后的新目标输入弹框、支线任务新增流程、副本开放提示方式和日记页时间线交互。
5. 搭建前端项目基础工程，包括路由、页面目录、全局状态管理、通用组件和 API 请求封装。
6. 先用 mock 数据或后端假接口完成页面静态开发，保证主要页面能串起来演示。
7. 与后端对齐接口字段，完成请求封装、错误态、空状态、加载态设计。
8. 接入真实接口并完成联调，保证任务、剧情、角色面板、日记和副本数据可以同步更新。
9. 增加比赛演示模式，包括剧情快捷触发、副本开放模拟和默认演示账号数据。
10. 完成前端自测，重点检查页面跳转、状态刷新、剧情展示和副本入口可用性。

### 重点页面交付物
- 注册界面高保真设计稿
- TODO-list 主界面设计稿
- 角色面板 / 商店设计稿
- 角色日记设计稿
- 副本页设计稿
- 新目标输入弹窗设计稿
- 通用组件规范与前端样式规范

### 前端验收标准
- 所有核心页面可访问，跳转关系正确
- 角色风格差异能被用户直观感知
- 任务完成后能看到明确成长反馈与剧情反馈
- 最后一个主线任务完成后会自动弹出新目标输入框
- 晚上 10 点副本入口状态展示清晰
- 在 mock 和真实接口两种情况下都能完成演示链路

## 11.2 后端任务书

### 目标
负责搭建业务数据结构、核心接口、AI 编排逻辑和副本时间规则，为前端提供稳定、可回退的服务能力。

### 初始任务清单
1. 输出 API 文档 V1，明确每个接口的入参、出参、字段含义、错误码和 mock 示例。
2. 确认核心数据模型，包括用户、Agent、目标、任务、剧情日记、装备技能、副本记录等结构。
3. 设计角色配置表，明确每个角色对应的故事风格、世界观模板、主线模板和展示字段。
4. 设计 AI 初始化流程，完成“目标拆解 + 世界观初始化 + 主线生成 + Agent 生成”接口。
5. 设计任务管理接口，支持查询任务、完成任务、修改任务、用户新增支线任务，并在最后一个主线任务完成后返回“需要输入新目标”的标识。
6. 设计剧情生成接口，支持根据任务完成记录生成成长反馈、章节更新和角色日记内容。
7. 设计角色成长接口，完成成长值、资源点、技能装备奖励的结算逻辑。
8. 设计商店与背包接口，支持技能装备查询、购买和装备状态更新。
9. 设计新目标接入接口，在主线阶段完成后接收用户新的阶段目标并重建主线任务。
10. 设计副本接口，包含副本开放状态查询、进入副本、结算副本、推进剧情四类能力。
11. 实现每天晚上 10 点开放副本的规则，并提供比赛演示所需的 mock 时间开关或快速开启能力。
12. 为 AI 能力准备降级方案，确保模型异常时仍可返回固定模板任务和剧情文本。
13. 完成接口自测与联调支持，输出 Postman/Apifox 测试集合或等价文档。

### 建议优先落地的核心 API
- `GET /api/roles`
- `GET /api/state`
- `POST /api/init`
- `POST /api/tasks/:taskId/complete`
- `POST /api/tasks/custom`
- `POST /api/goals/next`
- `POST /api/shop/purchase`
- `GET /api/dungeon/status`
- `POST /api/dungeon/start`
- `POST /api/dungeon/settle`

### 后端验收标准
- 所有核心接口有明确文档和稳定返回结构
- AI 接口异常时有可用降级结果
- 任务完成后能正确触发成长结算与剧情生成
- 最后一个主线任务完成后，后端会明确返回“需要输入新目标”的状态
- 支线任务能独立生成支线剧情
- 晚上 10 点副本规则和演示模式都能正常工作

## 11.3 前后端联调协作要求

### 第一批需要优先对齐的内容
- 页面清单与接口清单一一对应
- 用户、任务、剧情、角色面板的字段命名统一
- 角色风格配置字段统一
- 副本开放时间和演示模式的规则统一

### 联调建议顺序
1. 先对齐 API 文档和前端 mock 数据结构
2. 再联调注册初始化、任务列表和角色面板
3. 然后联调任务完成后的剧情生成、主线完成弹框和角色日记
4. 最后联调副本状态、进入和结算流程

### 最终比赛版验收链路
1. 完成注册和角色选择
2. 输入短期目标并获得主线任务与世界观
3. 完成任务并生成剧情
4. 最后一个主线任务完成后弹出新目标输入框，并成功生成新主线
5. 查看角色成长、角色日记和商店变化
6. 进入夜间副本并完成结果展示
